# Frozen native trial execution

Design contract for issue [#25](https://github.com/hwanjjang/agent-dotfiles/issues/25). The [operator guide](../native-trials.md) and [selected evidence](../verification/native-trials.json) record implemented commands and selected corrected-source V9/V10 qualification, preserving earlier V7/V8 evidence. This design contract defines their boundary; it does not grant comparison admission. The [credential-free fixture](native-execution-fixture.md) retains its separate contract.

## Purpose and supported boundary

A maintainer runs one frozen selected trial with fresh state before comparison. The selected arm, case, attempt, source bundle, client/executor/profile and declared limits are bound before authentication or launch. One supported profile is sufficient; do not infer every provider, client, host or tool is qualified. The first implementation targets the pinned Codex0.163 host app-server/code-mode runtime and a separately isolated Linux arm64 exec-server through an explicit existing Docker endpoint. Host support is qualified only where actually exercised. No VM, package, context, login, hook or real-account installation is implicit.

The trusted host supervisor/native client holds one temporary file credential copy and first-party transport. The Linux executor receives selected case/arm files and a verified readonly runtime volume, without host bind mounts, account/history, other arms, grader/answer material, provider credentials or Docker socket. The trusted native client/code-mode runtime is outside that OS boundary. Its pinned tool registry, selected environment, import resolver, empty effective hooks/MCP and disabled extensions are part of the boundary. A hostile trusted client, same-UID host attacker or kernel/container escape is outside this claim.

## Frozen input and caller interface

Provide one private, supervisor-owned selected-trial JSON manifest and a fresh output directory to the explicit runner. A nonexecuting check validates inputs without opening authentication or starting native/remote processes. Execution additionally requires an explicit credential-file path; there is no discovery, Keychain fallback, new login, account refresh/copyback or alternate model/provider fallback. Commands and endpoint selection are trusted operator inputs, never read from case Markdown.

The strict versioned manifest binds:

- trial/arm/attempt and selected case identity, experiment/binding digests where supplied by the frozen experiment, and a source-bundle digest; only the selected arm/case is materialized in the executor;
- a finite mapping of canonical relative regular-file paths and content digests for selected arm/case inputs, excluding credentials, other arms, checks/answers and graders; traversal, symlinks, hardlinks, unsafe types, duplicates and conflicting/reserved paths refuse;
- exact runner/component, host/native-helper, Linux executor archive and runtime/image identities, explicit Docker endpoint and declared profile/environment/capability roots;
- one requested model/reasoning profile, one initial turn, setup/observation/cleanup limits, post-use gross/output usage guards and retained-byte limits. Defaults cannot replenish an aggregate experiment budget.

Validate manifest schema/size, file identities and hashes, source/executable/runtime drift, unsafe paths, unsupported profile/transport and preexisting attempt/output/state before auth or native launch. Preserve original failures and reject duplicate attempts; creating another directory does not make the same attempt new. The fresh trial state contains only selected inputs and generated task-owned state. The executor cannot write the supervisor journal, receipt, graders or source inputs. A file digest binds bytes, not authority or trusted custody.

## Credentials and ownership

Read one explicit current-owner regular source file with exact0600 mode, one hardlink and at most1MiB through descriptor-relative nofollow traversal. Never parse, hash, log or return credential contents. Create the destination native home exclusively0700 and auth.json exclusively0600, recheck metadata during bounded copy and fsync. Record copy attempted separately from copy completed. A failed partial copy retains exact recovery identity when removal cannot be confirmed.

Use one native-home owner for normal and recovery cleanup. Unknown process shutdown retains auth. Once exact owned native/helper shutdown is confirmed, purge the known current0600 regular one-link auth file even if native atomically replaced it; then remove bounded same-owner/device native state. Only the pinned macOS apply_patch/applypatch alias pair under tmp/arg0-macos/codex-arg0 plus six ASCII alphanumeric characters is admitted, at most two links in one parent with exact verified executable target text. Recheck link metadata and unlink entries only; never open/stat/delete targets. Unknown types/identity changes/deadlines preserve incomplete residue. Project/staging/container/volume ownership remains separate. This is partial guarded cleanup, not forensic erasure or atomic deletion against a same-UID attacker.

## Runtime and model compatibility

Require exact owned native launch intent/completion and process identities before watching helpers. Watch only recorded native parents. A failed/malformed process query remains uncertainty; never silently ignore a possible owned process, accept a basename as canonical identity, or signal a reused/unrelated PID. Cleanup owns exact containers/volume identities and records independently observed absence before the external owner stops its dedicated VM. The runner never stops a shared VM or changes ambient Docker context.

After thread creation and before the initial model turn, inspect only models_cache.json in the fresh owned native home. Bound the read4MiB, require safe identity/type/links, strict JSON and exactly one requested model row; project only fixed typed tool-capability metadata. Refuse absent, duplicate, unsafe or incompatible metadata. Missing metadata means unknown, not Disabled. Disk metadata is a compatibility/refusal prerequisite, not proof of in-memory tool inventory, backend identity or future availability. Freeze the finite relevant metadata/profile/source fields and renew qualification on drift.

Use one selected remote environment with include_local=false and a plain selected capability root; require empty hooks, disabled host skills and empty effective MCP. Disable apps/plugins/web/memories/goals/collaboration and image generation under the supported profile. Retain actual dispatcher/import/MCP/OS checks: configuration labels and include_local=false alone do not establish denial. Any unexpected observed tool or route blocks qualification; no automatic allowlist growth. Raw native notifications are observations after dispatch, not a preventive approval handshake.

## Observation, receipts and stops

Never use the mock runner's raw archive for authenticated traffic. The supervisor retains bounded fixed-schema identity, terminal, numerical usage, limit, capability and cleanup facts outside executor mounts. Raw native prompts/tool input/output/errors/auth/challenge strings and their hashes are not retained. Declared source inputs have separate frozen identities; they are not raw native traffic. Final model text is discarded apart from an in-memory exact fixed qualification predicate. General task grading and later selected artifact admission belong to #26; terminal completion alone is not task correctness.

Require matching thread/turn identity and completed error-free terminal. Observe six separate total/last counters: totalTokens, inputTokens, cachedInputTokens, cacheWriteInputTokens, outputTokens and reasoningOutputTokens. Preserve missing fields and defaulting ambiguity. Never sum cumulative snapshots or add cache/reasoning subsets again. Retain first/latest/stop, diagnostics and at most64 changed snapshots plus one overflow snapshot, then cease persistence. Sink failure, missing required usage, discontinuity or retention failure blocks success. Summary mutation cannot alter stored observations.

A declared gross/output guard is post-use and can overshoot. Send at most one best-effort interrupt, with no new turn/retry and no renewed observation deadline; completed terminal after a stop remains stopped. One initial turn is not one wire request. Native aggregate usage is not billing or verified model identity. Record unknown provider retries/requests/charges explicitly. Apply bounded nonblocking native frames/streams, wall time and retained archive with dedicated cleanup/final receipt reserves. Retention failure must not erase primary failure or suppress owned cleanup.

Emit a typed source/trial/attempt/arm/environment-bound receipt with actual terminal, usage/stop, requested-versus-observed model facts and exact cleanup uncertainty. Failed and partial attempts remain reproducible, never overwritten or silently reclassified. Authentication, targeted access, boundary qualification and evaluator eligibility are distinct fields. Receipts do not self-authorize live comparison or promotion. Recovery requires the exact original journal/profile/source and independently reconciled process/resource state, never a caller success boolean.

## Current-profile qualification

Use known-existing synthetic protected host/account/history/other-arm/evaluator sentinels, with prior existence and unchanged bytes checked outside executor mounts. Selected command/skill paths and parent/symlink traversal must not expose them. Require successful selected command and skill body/reference controls. Exercise actual current network/root-write restrictions and finite IPv4/IPv6 errors; timeout/DNS ambiguity is not denial. No real account/history or unseen evaluation corpus is a canary.

The existing catalog also exposes patch/image/stdin and generic MCP/clock controls. Do not describe the profile as command-only while those remain callable. Retain small relevant outside-boundary patch/image/invalid-session guards; successful patch/image/PTY workflows are not promised. Unknown routes refuse qualification. Keep root-entry and nested-tool inventories distinct, and actual dispatcher behavior separate from names.

The selected V9 credential-free evidence is a private-coordinator attestation, with bridge/coordinator and receipt digests in the selected evidence record. The public `native_execution` runner returns `mock_complete` or `blocked`; it does not emit the private bridge status `coordinator_attested_credential_free_profile` (historically `qualified_credential_free_profile`). Outer sentinel/resource/VM checks belong to that separate attestation, not an implied public CLI capability. Preserve historical V7/V8 bindings alongside selected V9/V10 evidence, including protected-file verification after process shutdown, and renew evidence after relevant source changes.

Credential-free native probes may establish model-independent dispatch/OS denials on reconciled exact binaries/configuration/environment. They cannot replace actual authentication compatibility. One actual source-bound qualification turn can require exact fixed JavaScript, a bounded actual catalog/global/import projection, matching native call/output/thread/turn correlation and the remote-only random challenge. Any extra/unaccounted call or incomplete projection fails qualification. Exact-script observation is evidence, not a pre-dispatch code gate or natural routing test.

Retain a selected real failure/refusal with no local fallback and owned cleanup. Harness response deadline is not executor disconnect; label historical missing injections honestly. Reuse unchanged historical evidence only with explicit relevant source/profile/topology reconciliation; old images/host binds are not current named-volume proof. Renew affected checks on delivered public bytes.

## Verification and delivery

Focused synthetic tests cover frozen drift/duplicates/path safety beforeauth, source/destination custody and native replacement/aliases, usage persistence/soft-stop behavior, ownership/recovery and receipt reserves. A separate public CLI fake-process smoke exercises integrated wiring without authentication. Current exact-profile actual positive/negative/failure qualification remains separately identified. Update README/map, feature verification links and actual screenshot/PDF manual; check public contents and current CI, then obtain eligible independent PR review and CI. Integration follows explicit maintainer authorization; account activation/comparison/promotion remain excluded.

Primary implementation evidence follows pinned [app-server](https://learn.chatgpt.com/docs/app-server), [tool registration](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/core/src/tools/spec_plan.rs), [native aliases](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/arg0/src/lib.rs) and [skill catalog usage](https://github.com/openai/codex/blob/83086188ae0614bd882818ff1aa23f3194962012/codex-rs/ext/skills/src/catalog_prompt.rs) behavior. Current docs can drift; exact0.163 behavior is source-bound. No external code is adopted by this design; community validation for this exact profile remains limited.
