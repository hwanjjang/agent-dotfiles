# Qualify native observation delivery

Scenario ID: `native-observation`. Surface: observation CLI, installer and Claude/
Codex hooks. [The native guide](../../../../account/observation/native.md) owns
consent, commands, exact definitions and the dated platform matrix. Use disposable
configurations and synthetic content; never register real projects implicitly.

1. Run `python3 -m unittest discover -s tests -p 'test_observation*.py'` and the
   setup/account-doctor suites. Verify disabled/expired/revoked callbacks do not
   read input, exact-project scope, content exclusion, stable-ID replay, unknown
   outcomes and preserved observations across installer update/uninstall.
2. Select a committed candidate and one disposable client registration following
   the native guide. Default install adds no observer. Switching registration
   delivers only the newly selected client; unsupported-capability downgrade
   refuses. Confirm five Claude or four Codex routes alongside separate planning.
3. For Codex, compare the delivered observer definitions with native `/hooks`;
   only activate the exact definitions within existing authorization. Seven trusted
   planning hooks do not trust the four observer definitions. Native discovery is
   a prerequisite, not proof that each callback executed. Do not bypass trust or
   weaken sandbox settings to force a fixture to pass.
4. In a fresh authorized bounded client session, record actual model identity,
   read a synthetic file and exercise an intentional failure. Claude has a named
   PostToolUseFailure route; Codex PostToolUse retains unknown outcome even when
   the native shell trace reports nonzero exit. Inspect recorded kinds/counts and
   planning recovery independently. Do not infer missing callbacks or join nested
   tool IDs without an observed correlation contract.
5. Separate actual host evidence by client and environment. A blocked tool fixture
   with genuine callbacks is partial, not a full PASS. Initialization/SessionStart
   without usable authentication does not qualify model/tool/Stop behavior. WSL or
   subagent lineage needs its own evidence; do not reuse a macOS result for Linux.
6. Verify stored metadata excludes fixture contents, file paths, raw tool names,
   prompts and output. Inspect owned-file drift. Revoke, check old-epoch direct
   callback no-op, then remove the owned installation/state and retain private
   evidence. Label the post-revoke check as direct dispatcher proof if no native
   model turn was run.

Record exact runtime hashes/revision, client/model, event counts, blocked steps
and cleanup. The [Codex screenshot manual](../../../manual/codex-observation.json)
uses this scenario; browser-rendered results illustrate evidence without replacing
it. No metadata result establishes task success, complete delivery or efficacy.

## Capacity and attribution subset

Reuse this scenario ID for the [capacity guide](../../../../account/observation/capacity.md).
Run the observation suite plus `test_collector_qualification.py`, then use the
guide's bounded 10,000-callback command in a new ignored evidence directory. No
model/authentication is required. Check actual callback attempts against expected
ledger IDs, unique sequences, interrupted reservation evidence and unchanged replay
count; neutral stdout alone never establishes durable persistence. Report p95 and
its 50 ms target separately from capacity, retaining failed/incomplete attempts.

Check boundary manifests with disposable receipts: SessionStart/Stop freshness,
missing/oversized/changed receipts, component drift and budget refusal. Tool events
must not inherit a cached snapshot, historical imports must not borrow today's
receipt, and `effective_exposure_exact` must remain false. Preserve grant/epoch and
revocation checks before probes. No test of receipt identity qualifies model usage
or excludes a mid-turn edit. The [capacity walkthrough](../../../manual/collector-capacity.json)
illustrates these distinctions using browser-rendered actual benchmark summaries.
